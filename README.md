# ブラス・ライフ（brass-life）

吹奏楽部 × 学校生活 × 人生シミュレーション。Flutter Web で完全にオフラインで動きます。

- 中学1年の4月から高校3年の3月まで、1週＝1ターンで6年間（約310ターン）を過ごします。
- 実在の名称（学校・地名・大会・連盟）は使いません。名称はすべて生成した架空のものです。
- Firebase などの外部サービスは使いません。データは端末内（Web では IndexedDB）に保存します。
- 乱数は完全に決定論的です。**同じ Seed・同じ主人公の設定・同じ選択からは、必ず同じ人生になります。**
  逆に、練習の仕方や行動の選び方を変えれば、進学先・コンクールの結果・人間関係・称号まで変わります。

## 動かし方

```sh
flutter pub get
flutter run -d chrome          # 開発実行
flutter test                   # テスト（VM）
flutter test --platform chrome test/core test/domain   # Web でも同じ結果になるかの確認
flutter build web --release --no-web-resources-cdn      # 完全オフライン構成のビルド
```

生成コード（`*.g.dart` / `*.freezed.dart`）もコミットしているので、`build_runner` を実行しなくても動きます。
モデルを変更したときは `dart run build_runner build --delete-conflicting-outputs` を実行してください。

`main` に push すると GitHub Actions がテストを実行し、GitHub Pages に公開します。
公開するには、リポジトリの **Settings → Pages → Source** を「GitHub Actions」にしておく必要があります。

## 遊び方

1. タイトルで Seed を入力し（空欄ならランダム）、「この Seed で人生を始める」。
   続く「主人公をつくる」画面で、名前・性別・入学する中学校・入学前の音楽経験・性格（5 つの軸）・
   能力（音楽適性 6 種と学力・体力のポイント配分）を決められます。初期値は Seed が決めた主人公で、
   そのまま始めることもできます。
2. ホーム画面は学校の見取り図（ジオラマ）です。部員は性格・やる気・今週の行動に応じて
   パート室で練習していたり、廊下で談笑・口論していたり、中庭でサボっていたりします。
   **タップした相手・場所で今週の過ごし方が決まります。**
   - ★（自分）：基礎練／曲練／楽器メンテ／居残り練習
   - 部員：一緒に練習／教わる（自分より十分上手い同系統の相手）／指導する（その逆）／雑談
   - 場所：音楽室＝合奏練習、パート室＝パート練習、楽器庫＝メンテ、図書室＝勉強、中庭＝一息つく、校門＝遊びに行く・休養
   誰に近づくかで関係や上達が変わります（先輩を「指導」すると反感を買うことも）。
   合奏やオーディション・コンクール・定期演奏会では演出つきで結果が出ます。
   背景の色と環境音の設定は季節（春夏秋冬）と時間帯（放課後・夕暮れ）で変わります（音源は今後追加。現在は無音）。
   月の方針を決めて「月末までスキップ」「次のイベントまで進める」でまとめて進めることもできます。
3. 1年の主なイベント
   - 4月：担当楽器の決定（第3希望まで提出。適性・楽器の空き・先輩や顧問の考え方で決まる）
   - 5・7・10・12・2月：定期テスト（学期ごとに評定がつき、受験の内申になる）
   - 5月：**課題曲の選曲**。その年（中1〜高3＝1〜6年目）の課題曲 I〜IV から推す曲を選ぶ。
     曲ごとに求められる要素（リズム感・表現力・金管・スタミナなど）と、いまの部の実力が並んで表示され、
     相性が良いほどコンクールで有利になる。幹部・学生指揮か顧問の評価が高ければ推した曲がそのまま採用され、
     そうでなければ顧問が部に合う曲を選ぶ。画面右上の音符アイコンから全24曲の一覧を見られる
   - 6月：コンクールメンバーのオーディションとソリスト決定（アプローチカードを1枚選ぶ）
   - 7〜10月：コンクール（地区→県→支部→全国）。本番ごとにカードを選ぶ
   - 大会終了後：3年生の引退 → 秋に幹部選出（立候補／流れに任せる／辞退）
     - 立候補では役職（部長・代表／副部長／学生指揮／会計／セクションリーダー／パートリーダー。部の制度による）と、
       **なりたい気持ち**（5段階）を選びます。気持ちが強いほど選ばれやすくなりますが、
       選ばれなかったときは気持ちの強さ×役職の重みだけ **心の傷** を負います（最大で「部長に全てを懸けて」+60）。
     - 心の傷はやる気の戻る先を下げ、ストレスが下がりきらなくなり、上達も鈍らせます。
       週に1しか癒えず、雑談・遊び・一息つくと少し早まり、別の役職を勝ち取ると少し和らぎます。
     - 学生指揮は「表現の適性・音楽性・熟練度」で選ばれるので、基礎練や合奏で音楽性を育てるのが近道です。
   - 3月：定期演奏会
   - 中3・高3：推薦の打診（11月）→ 出願（1月）→ 合格発表（2〜3月）→ 卒業式
4. **退部**：ホーム画面の「部活を続ける？」から、理由（勉強に専念／心が疲れた／人間関係／ほかにやりたいこと）を選んで部を辞められます。
   合奏・パート練習・コンクール・定期演奏会・幹部選出から外れ、役職も失います。ストレスは軽くなりますが心の傷が少し増え、
   仲の良かった部員は寂しがり、部員・顧問からの信頼は下がります。退部中は練習しない週ごとに腕が鈍ります。
   「部に戻る」でいつでも再入部できますが、2回目以降は周りの目が冷たく、3年生の引退を迎えると戻れません。
   高校に進むと新しい部に入り直します。退部したまま卒業すると、それにふさわしい称号の候補になります。
5. 中学卒業後は進学先の高校で新しい部・制度のもとで続きます（中学の仲間と再会することもあります）。
6. 高校卒業後、6年間の記憶・実績・最終ステータスから **称号とエピローグ** が生成されます。
7. 画面右上のセーブボタンでスロット1〜3に保存できます（オートセーブは毎週）。タイトルの「続きから」で再開します。

右上の虫アイコンからは、世界の中身（全学校・全NPC・記憶）をデバッグ表示で確認できます。

Seed `TEST` の世界のフィンガープリントは `9EBA95EBDA15DF00`、同じ Seed で「練習漬け」の方針で6年間を自動で遊んだ最終状態のハッシュは `c0a28e89` で、
VM と Web（Chrome）のどちらでも一致します（ゴールデンテストで固定）。

## アーキテクチャ

```
lib/
├─ app/            ルーティング・テーマ・DI（Riverpod Provider）
├─ core/
│  ├─ rng/         決定論的乱数（xoshiro128** を 32bit 演算のみで実装）
│  └─ time/        実カレンダーに準拠した暦（DateTime に依存しない日付演算）
├─ domain/         Flutter に依存しない純 Dart
│  ├─ entities/        World, Region, School, Club, Npc, Player, MemoryTag …
│  ├─ value_objects/   楽器・性格・適性・関係性ベクトル・各種列挙型
│  ├─ master/          性格タグ定義・名前素材・実在名称ブロックリスト・記憶テンプレート
│  ├─ services/        世界生成（world_generation/）・索引・フィンガープリント
│  ├─ game/
│  │  ├─ models/       GameState（変化する値）・セーブの要約
│  │  ├─ master/       NPC の行動テーブル・アプローチカード
│  │  └─ engine/       TimeManager（進行）・行動・楽器決定・Drama Engine・オーディション・
│  │                   コンクール・幹部選出・定期演奏会・受験・進学・大学一覧・エンディング解析
│  │  └─ scene/        ジオラマのデータ（場所・人物の配置と状態・季節・時間帯・環境音の指定）
│  ├─ repositories/    抽象インターフェース
│  └─ usecases/        世界生成・決定性検証
├─ data/           Hive CE による永続化（JSON 文字列として保存し、schemaVersion を持たせる）
└─ presentation/   MVVM（各画面の View と ViewModel = Notifier / Provider）
```

### 決定論的乱数（`core/rng`）

- `dart:math` の `Random` は使いません（アーキテクチャテストで禁止しています）。
- **WorldSeedRng**: パス（例: `world/club/club_m07/member/2/13`）ごとに独立した乱数列を作ります。ある部の生成で乱数を余分に使っても、他の部の生成結果は変わりません。翌年度以降の新入生も同じ仕組みで遅延生成します。
- **SimulationRng**: `(WorldSeed, ターン, ドメイン, 主体, 選択)` から乱数列を作ります。同じターンに同じ選択をすれば必ず同じ結果になり、セーブ／ロードによる再抽選はできません。NPC ごとに独立した乱数列を使うため、ある NPC の行動が他の NPC の乱数をずらしません。
- Web（JS の数値）でも VM と同じ数列になるよう、演算はすべて 32bit の範囲に収めています。確率は万分率の整数で扱い、正規分布は Irwin–Hall 近似で生成します（`log` や `sin` は使いません）。

### 世界生成（`domain/services/world_generation`）

地域 → 学校（偏差値は層化抽選）→ 部の計画（強さ帯を構成比どおりに割当）→ NPC 総数の補正（1,000〜2,000 人）→ 部と部員の構築（保有楽器・過去の成績・学年構成・楽器の割当・熟練度）→ プレイヤー → 背景の記憶、の順に生成し、最後に整合性を検証します。

### ゲーム進行（`domain/game/engine`）

- `GameState` は世界本体を持たず（Seed から再生成）、変化する値だけを持ちます。
- 週の処理: プレイヤーの行動 → Drama Engine（NPC の自律行動・関係性・記憶）→ 次の週の開始処理（年度更新・各種イベント）。
- 入力が必要なイベントは `pending` に設定され、解決されるまで週は進みません。
- 関係性は有向ベクトル（好感・信頼・ライバル）で、変化には必ず理由つきの `MemoryTag` が残ります。

### 課題曲（`domain/game/master/set_pieces.dart` ほか）

- `Piece`（`domain/game/models/piece.dart`）: ID・曲名・年（1〜6）・番号（I〜IV）・種別・URL・同梱音源パス・要求ステータス。
- 全24曲のマスターは `SetPieces`。UI からは `PieceRepository`（実装は `data/repositories/master_piece_repository.dart`）経由で使う。
- 部の実力（`PieceFit.bandStats`）と曲の要求の相性が、選曲とコンクールの評価に反映される。
- **アプリ内で聴ける**: 選曲画面・課題曲一覧の ▶ ボタンで再生（画面下のミニプレイヤーで一時停止・停止）。
  コンクール本番の演出中は、その年の課題曲が流れる。
  - 既定では Suno の配信用 MP3（`https://cdn1.suno.ai/{曲ID}.mp3`）をネット経由で再生する。
  - **Suno から手動で保存した音源を取り込むには** 各曲ページの「…」→ Download → MP3 Audio で保存し、
    `dart run tool/import_pieces.dart <保存したフォルダ>` を実行する（ファイル名の曲名から自動で振り分ける）。
  - **オフラインで鳴らすには** `dart run tool/download_pieces.dart` を実行すると、24 曲を
    `assets/audio/y{年}_{番号}.mp3`（例: `y1_I.mp3`）に保存する。手動で置く場合も同じ名前で（`.wav` / `.m4a` も可）。
    置いた音源はネットより優先され、`flutter run` / `build` をやり直すと反映される。
  - 再生部分は `AudioEngine`（`presentation/game/pieces/piece_player.dart`）として分けてあり、実装は audioplayers。

### ジオラマ（`domain/game/scene` と `presentation/game/scene`）

- **データ層**: `ClubSceneService` が GameState から「誰が・どこで・何をしているか（`SceneActor`）」を決定論的に組み立てます。
  場所（`SceneLocation`）は 1000×1000 の見取り図上の矩形と「そこでできる行動」を持ち、
  NPC の配置は直近の自律行動・やる気・ストレスから、表情（`ActorMood`）や二人組（`partnerId`）も含めて決まります。
  どこで誰に何ができるかは `InteractionRules` が決め、実行時（`TimeManager.submitAction`）にも同じルールで検証します。
- **表示層**: `DioramaView`（Stack + AnimatedPositioned）、`ScenePalette`（配色・アイコン）、
  `PerformanceStage`（色調変化・音符のパーティクル・枠の発光）、`AmbientAudio`（環境音の再生口、既定は無音）。
  絵や音を差し替えても、データ層とゲームの結果は変わりません。
